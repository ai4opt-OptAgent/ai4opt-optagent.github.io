ICLR 2024 / Modeling agents & reasoning

Chain-of-Experts: When LLMs Meet Complex Operations Research Problems

Ziyang Xiao, Dongxiang Zhang, Yangjun Wu, Lilin Xu, Yuan Wang, Xiongwei Han, Xiaojin Fu, Tao Zhong, Jia Zeng, Mingli Song, Gang Chen

Read the paper↗Code↗Cite this work

Chain-of-Experts improves complex optimization modeling and code generation through specialized LLM agents, dynamic coordination, and feedback-driven backward reflection.

01 / Research question

Complex operations research problems often contain implicit constraints, specialized terminology, and interdependent decision variables that require domain knowledge and multi-step reasoning. Traditional natural-language optimization modeling methods mainly target simpler linear programming problems with explicit descriptions. Directly prompting an LLM to generate formulations and code can also lead to missing constraints and reasoning errors. This work investigates how specialized language-model agents can collaborate to interpret problem statements, construct mathematical models, generate executable programs, and correct mistakes through structured feedback.

02 / Approach

Chain-of-Experts configures specialized LLM agents for tasks such as terminology interpretation, domain knowledge supplementation, variable and constraint extraction, mathematical modeling, programming, and code review. Given a natural-language problem, a Conductor dynamically selects experts according to the current reasoning state, progressively collecting their contributions. Experts may retrieve relevant information from external knowledge bases when available. A Reducer then consolidates potentially fragmented or conflicting contributions into a candidate formulation and executable program. The program is evaluated in an external execution environment. If an error is detected, backward reflection revisits the selected experts in reverse order to identify the responsible step and provide corrective feedback. The system subsequently resumes forward reasoning and program generation, repeating the process until the evaluation passes or the iteration limit is reached.

03 / Research scope

Evaluation uses 289 LPWP test problems and the newly constructed 37-problem ComplexOR benchmark, covering elementary linear programming and complex supply chain, scheduling, and logistics problems. Main experiments use GPT-3.5-turbo, with additional evaluations using GPT-4 and Claude 2. Accuracy measures whether generated programs pass expert-annotated test cases; compilation and runtime error rates are also reported. Expert collaboration is prompt-driven and requires no additional base-model training.

LPWP contains 289 test problems; ComplexOR contains 37 problems, each with at least five expert-annotated test cases. The uniform-role variant uses the same generic system prompt for all roles and removes expert knowledge bases.

The uniform-role variant already benefits from the cooperative workflow, while specialized experts provide an additional gain. This suggests that collaboration structure and domain-specific roles contribute at different levels: one organizes reasoning and correction, while the other helps interpret the terminology and implicit requirements of the optimization problem.

Without Conductor: select experts at random. Without Reducer: extract the answer from concatenated raw expert comments.

Expert summarization has a particularly strong effect on ComplexOR, making information flow a central part of multi-agent design. Downstream experts need concise, coherent context rather than an accumulation of raw comments. The Conductor and Reducer complement this by selecting who contributes next and reconciling what has already been said; backward reflection then uses execution feedback to revisit the steps that need correction.
