ICML 2026 / Verification & correction

SAC-Opt: Semantic Anchors for Iterative Correction in Optimization Modeling

Yansen Zhang, Qingcan Kang, Yujie Chen, Yufei Wang, Xiongwei Han, Tao Zhong, Mingxuan Yuan, Chen Ma

Read the paper↗Code↗Cite this work

SAC-Opt compares the semantics of generated optimization code with explicit anchors for the original constraints and objective. It locates mismatched components and corrects them individually.

01 / Research question

Generated optimization code can run successfully while encoding the wrong business rule. How can a modeling system detect these silent semantic errors and revise the specific constraints or objective responsible?

02 / Approach

SAC-Opt first extracts parameters, variables, constraints, and the objective into a structured representation. Parameters and variables are rendered through templates, while constraints and the objective form the semantic anchors used for verification. After generating code, the system reconstructs these anchors from the implementation and compares them with the originals. Feedback identifies mismatched components for targeted revision; the loop repeats until the anchors align or the iteration limit is reached. A final solver-debugging stage handles execution errors. This separates checking what the program means from checking whether it runs.

03 / Research scope

Evaluation covers seven public optimization modeling datasets, from elementary linear programming to industrial and complex OR problems. The main comparison uses a unified GPT-4o setup and averages five independent runs. Accuracy requires executable code, a correct objective value, and a correct optimal solution. Further analyses examine component ablations, an alternative backbone, and LLM-based versus similarity-based semantic verification.

Accuracy requires executable code and both a correct objective value and optimal solution. Standard, Chain-of-Thought, Chain-of-Experts, and CAFA results are reproduced from the survey in the same setting. Other baselines use their official implementations where available.

SAC-Opt outperforms the compared methods on all seven benchmarks. The pattern supports retaining the original problem semantics as an explicit reference throughout generation: solver execution supplies feedback about implementation, while anchor comparison directs revision toward whether constraints and the objective express the intended requirements.

Accuracy requires executable code and both a correct objective value and optimal solution. Semantic correction aligns model elements with problem intent. Solver debugging handles execution errors after semantic correction.

Removing semantic correction causes a larger loss than removing solver debugging on every benchmark. The two stages address different failure modes: an executable program may still encode the wrong model, while a semantically aligned formulation still needs a working implementation. Their complementary roles make semantic diagnosis an essential part of the correction workflow.
